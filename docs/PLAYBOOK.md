# PLAYBOOK — як ми робимо серію

> Зона Claude A (продакшн і контент). Шаблон v0 — наповнюємо з досвідом.
> Кожен урок з продакшну → сюди (як робити) або в `MEMORY.md` → «Що не працює».

## 0. Нова історія

Тека `series/<slug>/` (приклад — `series/la-garganta/`):
1. `bible.yaml` — логлайн, жанр, місце дії й акцент, **правила світу**, персонажі з **візуальною ДНК**
   (3–4 незмінні ознаки), голоси, локації, табу, ризики.
2. `story.md` — 4 частини бітами з мітками (розділ 3).
3. `clues.md` — ланцюжок підказок для детективу: що посіяно, де, що означає, де розкрито.
4. Референси персонажів і локацій (етап refs) → людина затверджує → маніфест у Git, файли в R2.

Відкладені історії лежать у `series/_archive/`.

**Контракт з фабрикою.** Таблиці `story.md` читає `fabrica/story.py`, а `script.json` звіряється з ними «без втрат»
(`check_script`). Тому формат фіксований:
- 5 колонок: `#` · `~час` · `Біт` · `Мітки` · `Підказки`;
- час мітки — `(~m:ss)` у дужках;
- підказки — `+C05` / `!C05`, хибні сліди — «хибний слід F1» / «F2 спростовано»;
- репліки — `_«…»_`.

Змінюєш формат → `uv run pytest tests/test_models.py` і лист Claude B. ID у `bible.yaml` / `clues.md` теж
читає код (`fabrica/bible.py`), тож перейменування id — лише разом з B.

## 1. Частина

| Крок | Хто | Що перевірити перед наступним |
|---|---|---|
| Біти частини в `story.md` | A + людина | мітки на місці, підказки з `clues.md` посіяні/розкриті, **хук-обрив** |
| script | фабрика | хронометраж 6–8 хв, жива іспанська, мітки перенесено |
| shots | фабрика | 1–10 с на шот (`SCREAMER` — 0,5–2 с), різноманіття планів, промпти без заборонених слів |
| refs / voice | фабрика | ДНК персонажів у кожному кадрі, голоси впізнавані, вимова імен правильна |
| video → qc → repair | фабрика | обличчя консистентні, без артефактів; ліміт спроб |
| assemble | фабрика | ритм, гучність, субтитри; після 4-ї частини — Película completa |
| cut | фабрика | тизер 30–40 с за мітками `TEASER{n}`, перші 2 с чіпляють, **обривається на хуку** |
| publish | людина підтверджує | назва/опис/теги ES, позначка AI, обкладинка; 2 частини на тиждень |

## 2. Формат історії

- **Історія = 4 частини по 6–8 хв** (YouTube, 16:9), по 2 частини на тиждень.
- Після 4-ї частини — **Película completa** на 25–30 хв: частини підряд, без рекапів і заставок «Continuará…».
- До кожної частини — 1+ тизер 30–40 с (TikTok / Shorts, 9:16).

## 3. Мітки бітів

Їх ставимо в `series/<slug>/story.md`, а фабрика переносить у `script.json` / `shots.json`.
Перелік фіксований: нову мітку додаємо лише через `/decision` і лист Claude B, бо від неї залежать схеми.

| Мітка | Що це | Правила |
|---|---|---|
| `HOOK_OPEN` | Перші 5–15 с частини | Подія або питання одразу, без «розгону» і без рекапу перед ним. Одна на частину. |
| `MIDPOINT` | Поворот посередині частини | Змінює напрям або ставки: героям уже не повернутися до того, що було. Один на частину. |
| `SCREAMER` | Скрімер (jump scare) | 0,5–2 с: раптова поява чи рух + різкий звуковий удар. Перед ним 3–10 с тиші або наростання. Не більше 1–2 на частину. **У тизер — лише як `TEASER_CUT_BEFORE`** (обрив перед ударом). |
| `TEASER{n}_START` | Початок тизера n | n = 1, 2, … в межах частини. Звідси тизер має бути зрозумілим без контексту. |
| `TEASER{n}_CUT_BEFORE` | Тизер n обривається ПЕРЕД цим моментом | Кадр, репліка чи звук, які дали б відповідь. Від `_START` — 30–40 с. |
| `CLIFF` | Кліфхенгер у кінці частини | Частини 1–3 — нове питання, сильніше за закрите. Частина 4 — розв'язка + гачок на продовження. |

## 4. Правила хука для тизерів

- Обрив за мить до відповіді: репліка недоговорена, двері відчиняються, правда от-от відкриється.

## 5. Лабораторія промптів — спершу люди, потім автомат

Платні виклики вимкнені (`AUTOMATION_ENABLED=false`). Програма видає **рівно ті промпти й параметри**, які відправила б
в API, люди тестують їх руками, і лише затверджені (golden) версії потім бере автоматика. Як пишемо промпти під кожну
модель (і чому) — [docs/research/2026-10-07-generators.md](research/2026-10-07-generators.md).

**Робоче місце — студія:** `uv run fabrica studio` (відкриється в браузері; `--sequence first30` — одразу перші 30 с).
Студія показує лише потрібне для вибраної послідовності, у **порядку виробництва**, і пам'ятає, де ми зупинились
(«Далі →»). Статичний пакет для телевізора — як і раніше: `uv run fabrica prompts la-garganta <набір>`.

**Кроки (1–7):** 1 обличчя-якорі (Nano Banana Pro) → 2 ракурси, емоції, мокрі (Nano Banana 2.1, Image 1 = якір) →
3 локації (плити без людей) → 4 голоси (ElevenLabs Voice Design) → 5 стартові й кінцеві кадри (Image 1 = локація, далі
люди зліва направо) → 6 відео (Seedance 2.5) → 7 репліки (ElevenLabs v4). На картці — що прикріпити й у якому порядку,
стан кожного референсу («✓ є 5/5» / «ще немає — спершу крок N»).

1. **Взяти промпт:** «Копіювати промпт» → вставити в інструмент з картки (перша інструкція відкрита):
   - фото — AI Studio / Gemini тією самою моделлю (якорі облич — Nano Banana Pro; є й у dropshot → Image);
   - відео — **dropshot AI Studio → Video → Seedance 2.5 → Frame to Video**: Start frame (і End frame, якщо є) — файли з
     картки; **16:9 · тривалість із картки · 720p · With Audio ON · Draft OFF**. Окремого негативу немає — заборони вже
     в промпті («No subtitles…», «No BGM…»);
   - голос — ElevenLabs (JSON з картки).
2. **Тести відео — на одному платному акаунті** (рішення 07.10): та сама модель і параметри, що в автоматиці
   (Seedance 2.5, 720p, кліп = довжина шоту 4–10 с). Ліміт «перших 30 с» — **$40**; студія рахує витрачене
   («$ x / 40 · ще ≈ N проходів»; один прохід ≈ $8,32). Короткий шот (1–3 с) генеруємо 4 с — у монтаж іде **вікно з
   картки**. `handoff: continue` — старт = останній кадр попереднього кліпу (студія вирізає його сама з записаного відео).
3. **Записати результат:** у картці — інструмент, оцінка 1–5, нотатки, файл (перетягнути) → «Записати». Оцінка ≥ 4 —
   статус «Готово». Або в Terminal: `uv run fabrica lab log <id> --tool dropshot --score 4 --file … --notes "…"`.
4. **Не вийшло → «Редагувати промпт»:** описати словами, що не так («промінь ліхтаря двоїться», «обличчя пливе»).
   Переписувач (Ollama на Mac; пізніше — Claude: `REWRITE_BACKEND=claude`) пропонує зміну опису шоту й **урок**;
   «Застосувати» → зміна в `series/<slug>/lab/overrides.yaml`, урок — у `lessons.yaml`. Уроки автоматично
   додаються в усі наступні промпти того ж типу, щоб помилка не повторювалась (`uv run fabrica lab lessons` — список).
5. **Golden:** «Затвердити golden» на картці або `uv run fabrica lab approve <шаблон|елемент>`. Потрібен результат з
   оцінкою ≥ 4 для поточної версії промпту. Змінився промпт — golden знімається сам.
6. **Автомат:** коли все потрібне golden і люди ввімкнуть `AUTOMATION_ENABLED=true`, фабрика генерує тими самими
   промптами, сідами й референсами. Обличчя до камери — маршрут Cloudflare (`use_virtual_avatar`): Replicate фотореальні
   обличчя Seedance 2.x відхиляє (E005), навіть згенеровані.

**Оцінка 1–5:** 5 — ідеально, у кадр; 4 — придатно з дрібницями; 3 — ідея є, деталі погані; 2 — не те; 1 — брак.
Нотатки пиши конкретно: що саме не так (ДНК, руки, текст у кадрі, фізика, світло, звук) — з них студія робить уроки.

**Правила промптів (коротко):** перший кадр — це перша мить кліпу (розкриття — до розкриття); у відео не переописуємо
зовнішність — лише теги («жінка в чорній джинсовій куртці») і стани; одна камера на кліп; дія з кінцевим станом;
без слів про вік (boy / girl / teen / young), «fast», «VHS», тексту в кадрі; звук — конкретні шуми, без музики; репліка —
мовою й акцентом («Mexican Spanish, Mexico City accent») у лапках. Лінтер (`prompts/lint.yaml`) і перевірка схеми API
(`prompts/providers.yaml`) показують порушення на картці.
