# PLAYBOOK — як ми робимо серію

> Зона Claude A (продакшн і контент). Шаблон v0 — наповнюємо з досвідом.
> Кожен урок з продакшну → сюди (як робити) або в `MEMORY.md` → «Що не працює».

## 0. Нова історія

Тека `series/<slug>/` (приклад — `series/la-garganta/`):
1. `bible.yaml` — логлайн, жанр, місце дії й акцент, **правила світу**, персонажі з **візуальною ДНК**
   (3–4 незмінні ознаки), голоси, локації, табу, ризики.
2. `story.md` — 4 частини бітами з мітками (розділ 3).
3. `clues.md` — ланцюжок підказок для детективу: що посіяно, де, що означає, де розкрито.
4. Референси персонажів і локацій (етап refs) → людина затверджує → маніфест у Git, файли в R2.

Відкладені історії лежать у `series/_archive/`.

**Контракт з фабрикою.** Таблиці `story.md` читає `fabrica/story.py`, а `script.json` звіряється з ними «без втрат»
(`check_script`). Тому формат фіксований:
- 5 колонок: `#` · `~час` · `Біт` · `Мітки` · `Підказки`;
- час мітки — `(~m:ss)` у дужках;
- підказки — `+C05` / `!C05`, хибні сліди — «хибний слід F1» / «F2 спростовано»;
- репліки — `_«…»_`.

Змінюєш формат → `uv run pytest tests/test_models.py` і лист Claude B. ID у `bible.yaml` / `clues.md` теж
читає код (`fabrica/bible.py`), тож перейменування id — лише разом з B.

## 1. Частина

| Крок | Хто | Що перевірити перед наступним |
|---|---|---|
| Біти частини в `story.md` | A + людина | мітки на місці, підказки з `clues.md` посіяні/розкриті, **хук-обрив** |
| script | фабрика | хронометраж 6–8 хв, жива іспанська, мітки перенесено |
| shots | фабрика | 1–10 с на шот (`SCREAMER` — 0,5–2 с), різноманіття планів, промпти без заборонених слів |
| refs / voice | фабрика | ДНК персонажів у кожному кадрі, голоси впізнавані, вимова імен правильна |
| video → qc → repair | фабрика | обличчя консистентні, без артефактів; ліміт спроб |
| assemble | фабрика | ритм, гучність, субтитри; після 4-ї частини — Película completa |
| cut | фабрика | тизер 30–40 с за мітками `TEASER{n}`, перші 2 с чіпляють, **обривається на хуку** |
| publish | людина підтверджує | назва/опис/теги ES, позначка AI, обкладинка; 2 частини на тиждень |

## 2. Формат історії

- **Історія = 4 частини по 6–8 хв** (YouTube, 16:9), по 2 частини на тиждень.
- Після 4-ї частини — **Película completa** на 25–30 хв: частини підряд, без рекапів і заставок «Continuará…».
- До кожної частини — 1+ тизер 30–40 с (TikTok / Shorts, 9:16).

## 3. Мітки бітів

Їх ставимо в `series/<slug>/story.md`, а фабрика переносить у `script.json` / `shots.json`.
Перелік фіксований: нову мітку додаємо лише через `/decision` і лист Claude B, бо від неї залежать схеми.

| Мітка | Що це | Правила |
|---|---|---|
| `HOOK_OPEN` | Перші 5–15 с частини | Подія або питання одразу, без «розгону» і без рекапу перед ним. Одна на частину. |
| `MIDPOINT` | Поворот посередині частини | Змінює напрям або ставки: героям уже не повернутися до того, що було. Один на частину. |
| `SCREAMER` | Скрімер (jump scare) | 0,5–2 с: раптова поява чи рух + різкий звуковий удар. Перед ним 3–10 с тиші або наростання. Не більше 1–2 на частину. **У тизер — лише як `TEASER_CUT_BEFORE`** (обрив перед ударом). |
| `TEASER{n}_START` | Початок тизера n | n = 1, 2, … в межах частини. Звідси тизер має бути зрозумілим без контексту. |
| `TEASER{n}_CUT_BEFORE` | Тизер n обривається ПЕРЕД цим моментом | Кадр, репліка чи звук, які дали б відповідь. Від `_START` — 30–40 с. |
| `CLIFF` | Кліфхенгер у кінці частини | Частини 1–3 — нове питання, сильніше за закрите. Частина 4 — розв'язка + гачок на продовження. |

## 4. Правила хука для тизерів

- Перші 1–2 с — сильна емоція або питання, без «розгону».
- Обрив за мить до відповіді: репліка недоговорена, двері відчиняються, правда от-от відкриється.

## 5. Лабораторія промптів — спершу люди, потім автомат

Платні виклики вимкнені (`AUTOMATION_ENABLED=false`). Програма видає **рівно ті промпти**, які відправила б в API,
люди тестують їх руками, і лише затверджені (golden) версії потім бере автоматика.

1. **Пакет:** `uv run fabrica prompts la-garganta casting` (обличчя, локації, голоси), `… test-pack` (тест-пак),
   `… 1` (частина: стартові кадри, відео, репліки). Відкрий `prompts/out/la-garganta/<набір>/index.html`
   (телевізор/браузер): промпт з кнопкою «копіювати», negative, параметри (модель, розмір, сід, роздільність,
   тривалість), які референси прикріпити.
2. **Тест руками:** Gemini / Nano Banana (фото), SYNTX / Dreamina / Replicate playground (відео), ElevenLabs
   (голос). Сід і параметри — з картки. Референси — файли, що вже пройшли тест (їхні мініатюри видно на картці).
3. **Запис:** у картці заповни нотатки, інструмент, оцінку, шлях до файлу → «Копіювати команду журналу» →
   вставити в Terminal. Або руками: `uv run fabrica lab log <id> --tool gemini --score 4 --file … --notes "…"`.
   Файл копіюється в `media/lab/` (не в Git), запис — у `lab/results.yaml` (у Git) з версією шаблону й промпту.
4. **Правка:** не вийшло → правимо шаблон `prompts/templates/<kind>/<…>.yaml` (і піднімаємо `version`) або
   англійський опис `series/<slug>/prompt_en.yaml` → перегенеруй пакет → тест знову.
5. **Golden:** `uv run fabrica lab approve <шаблон>` (напр. `image.start_frame`) або `<елемент>` (напр.
   `tp-T1-frame`). Потрібен хоча б один результат з оцінкою ≥ 4 для поточної версії. Правка golden-шаблону без
   нової версії ламає golden — `uv run fabrica lab status` це покаже.
6. **Автомат:** коли все потрібне golden і люди ввімкнуть `AUTOMATION_ENABLED=true`, фабрика генерує тими самими
   промптами, сідами й референсами (Replicate для відео).

**Оцінка 1–5:** 5 — ідеально, у кадр; 4 — придатно з дрібницями; 3 — ідея є, деталі погані; 2 — не те; 1 — брак.
Нотатки пиши конкретно: що саме не так (ДНК, руки, текст у кадрі, фізика, світло) — з них правимо шаблони.
