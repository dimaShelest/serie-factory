# ARCHITECTURE — конвеєр serie-factory

> Чернетка v0 (Claude A, 2026-10-05). Код етапів пише Claude B (`fabrica/`), промпти й контент —
> Claude A (`fabrica/prompts/`, `series/`). Зміни архітектури — через `/decision`.

## Стек

Python 3.12 + uv · Typer (CLI `fabrica`) · Pydantic (моделі й валідація) · FFmpeg (монтаж) ·
SQLite (стан конвеєра й витрати) · R2 (медіа) · Claude API (сценарій) · Seedance (відео) ·
ElevenLabs (голос) · IMAGE API (референси) · Sync (lip-sync) · YouTube Data API (публікація).

## 10 етапів

Кожен етап — окрема команда `fabrica <етап> <серіал> <серія>`. Етапи **ідемпотентні**: вхід хешується,
і повторний запуск без змін нічого не генерує й нічого не коштує.

| # | Етап | Вхід | Вихід | Сервіс |
|---|---|---|---|---|
| 1 | **script** | біблія серіалу, план серії | `script.json`: сцени, репліки (ES), ремарки, позначка хука | Claude API |
| 2 | **shots** | script | `shots.json`: шоти 3–10 с — план, камера, дія, промпт відео, репліки шота | Claude API |
| 3 | **refs** | біблія (персонажі, локації), shots | референс-зображення персонажів і локацій, кеш за хешем | IMAGE API |
| 4 | **voice** | script, голоси персонажів | `wav` на кожну репліку + тривалості (вони задають довжину шота) | ElevenLabs |
| 5 | **video** | shots, refs, voice | кліп на шот (image-to-video), lip-sync для шотів з діалогом | Seedance, Sync |
| 6 | **qc** | кліпи | оцінка кожного шота: тривалість, артефакти, консистентність облич, відповідність промпту | FFmpeg + vision-LLM |
| 7 | **repair** | шоти, що не пройшли qc | перегенерація (ліміт спроб і бюджету), інакше — позначка для людини | як у 3–5 |
| 8 | **assemble** | кліпи, аудіо, музика | серія 16:9: склейка, субтитри ES, гучність −14 LUFS | FFmpeg |
| 9 | **cut** | серія + позначка хука | тизер 9:16 30–40 с: найсильніший момент → обрив на хуку, reframe, впалені субтитри | FFmpeg |
| 10 | **publish** | серія, тизер, метадані ES | завантаження на YouTube (+ Shorts), майстри в R2; TikTok — поки вручну | YouTube API, R2 |

### Наскрізне: облік витрат

- Кожен платний виклик іде через одну обгортку: перед викликом — **оцінка й перевірка ліміту**,
  після — запис факту в SQLite (`costs`: час, серіал, серія, етап, провайдер, одиниці, USD, хеш входу).
- Ліміти з `.env`: `BUDGET_PER_EPISODE_USD`, `BUDGET_DAILY_USD`, `BUDGET_MONTHLY_USD`.
  Від 80 % — попередження, від 100 % — **жорстка зупинка** (продовжити можна лише явним прапорцем).
- `fabrica costs` — звіт; `docs/COSTS.md` — людський підсумок, оновлюється на `/handoff`.

## Дані

```
series/<slug>/               # Git, зона A: біблія, персонажі, голоси, плани серій
  bible.md  characters/  episodes/E01/outline.md
fabrica/prompts/<етап>/      # Git, зона A: шаблони промптів генерації
fabrica/                     # Git, зона B: код етапів, CLI, моделі
output/<slug>/E01/<етап>/    # НЕ в Git: згенероване (json, wav, mp4); майстри → R2
output/fabrica.sqlite        # НЕ в Git: стан етапів і витрати
```

Між етапами передаються JSON-файли за Pydantic-схемами (`fabrica/models.py`), щоб будь-який етап
можна було перезапустити окремо. Схеми `script.json` і `shots.json` погоджують A і B: A відповідає
за зміст, B — за код.
